
# ADR-006: Використання HTTP 403 та 404

**Статус:** Прийнято

## Контекст

У EventHub реалізовано рольову модель доступу
та перевірку власності подій.

Необхідно визначити, яку відповідь повертати
при відмові у доступі.

## Рішення

### HTTP 401 Unauthorized

Повертається, коли користувач не автентифікований
або його access-токен недійсний.

### HTTP 403 Forbidden

Повертається, коли користувач автентифікований,
але його роль не дозволяє виконати операцію.

Приклад: користувач із роллю USER намагається
відкрити /organizer/events.

### HTTP 404 Not Found

Повертається, якщо запис відсутній або не
належить поточному організатору.

Приклад: організатор А намагається змінити
подію організатора Б.

## Реалізація

Перевірка власності виконується безпосередньо
в умові WHERE запиту Prisma.

Для редагування використовується updateMany
з умовами id та organizerId.

Якщо кількість змінених записів дорівнює нулю,
сервер повертає HTTP 404.

## Наслідки

- Користувачі не отримують інформації про
  існування чужих приватних ресурсів.
- Рольова авторизація відокремлена від
  перевірки власності.
- Доступ адміністратора може охоплювати
  всі події відповідно до його ролі.
